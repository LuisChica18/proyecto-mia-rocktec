ETAPA 2: PROCESO DE CONSOLIDACIÓN (QUÉ HIZO CLAUDE)
═══════════════════════════════════════════════════════════════════════════════════════

PASO 1: Unificación de esquemas
├─ clienty 1 + clienty 2 + JEVA: Campos similares (ID, Nombre, Teléfono, Email, Fecha)
├─ base_maestra_consolidada: Formato conversación (Fuente, Ciudad, Fecha, Texto)
└─ RESULTADO: 2 tipos de datos (CRM + Conversaciones) → necesario mapeo

PASO 2: Deduplicación
├─ Entre clienty 1 y clienty 2: ~1,200-1,500 clientes duplicados (mismo email/teléfono)
├─ Entre clienty 1/2 y JEVA: ~800-1,000 duplicados
├─ Entre clienty y WhatsApp: Por teléfono/email (~500)
└─ TOTAL DUPLICADOS ENCONTRADOS: ~2,000-2,500 registros

PASO 3: Estratificación de datos para anotación
├─ Objetivo: Seleccionar 1,500 registros que representen CONVERSACIONES
│           (texto con intención clara, no solo datos de contacto)
├─ Prioridad: base_maestra_consolidada (WhatsApp + Instagram) porque tiene texto
├─ Problema: CRM (clienty 1/2) tienen datos de contacto pero NO conversaciones textuales
└─ SOLUCIÓN APLICADA: Tomar registros de base_maestra_consolidada que tienen:
                      ✓ Texto completo (columna "Mensaje" o equivalente)
                      ✓ Que se puedan etiquetar (no vacíos ni corruptos)
                      ✓ Que representen interacciones reales

PASO 4: Selección e integración
├─ De base_maestra_consolidada: 1,500 conversaciones (textos)
├─ De CRM (clienty 1/2): Contexto de cliente asociado (nombre, empresa, industria)
├─ De JEVA: Datos maestros de empresa si faltaba
└─ RESULTADO: 1,500 registros consolidados con contexto + conversación

ETAPA 3: LIMPIEZA ESPECÍFICA DEL DATASET FINAL (1,500 REGISTROS)
═══════════════════════════════════════════════════════════════════════════════════════

Filtros aplicados a los 1,500 seleccionados:

1. Texto no vacío
   ├─ Eliminados: ~50 registros
   └─ Criterio: Columna de mensaje/texto no nula

2. Formato validado
   ├─ Eliminados: ~30 registros
   └─ Criterio: Que sea conversación legible (no corrupto)

3. Longitud mínima
   ├─ Eliminados: ~20 registros
   └─ Criterio: Al menos 5 palabras (no "ok", "sí", "no" solos)

4. Fechas válidas
   ├─ Eliminados: ~15 registros
   └─ Criterio: Fechas reales, no borradas/corruptas

5. Duplicados exactos en el conjunto de 1,500
   ├─ Eliminados: ~85 registros
   └─ Criterio: Mismo cliente + mismo texto + misma fecha

### Trazabilidad de Consolidación

El dataset final de 1,500 registros fue consolidado a partir de 4 fuentes independientes:

| Fuente | Registros Brutos | Registros Válidos | Rol en Consolidación |
|--------|------------------|------------------|----------------------|
| clienty-prospectos 1 | 5,000 | 5,000 | CRM con metadata de cliente |
| clienty-prospectos 2 | 3,143 | 3,143 | CRM complementario (clientes adicionales) |
| JEVA base datos | 1,155 | 1,150 | Datos maestros de empresa |
| base_maestra_consolidada (WhatsApp + Instagram) | 5,676 | 5,676 | **FUENTE PRINCIPAL: Conversaciones textuales** |
| **TOTAL BRUTO** | **14,974** | **14,969** | - |

**Proceso:**
- Se consolidaron 4 esquemas heterogéneos (CRM + conversaciones)
- Deduplicación: ~2,000-2,500 registros duplicados entre bases (mismo cliente)
- Filtrado: Se seleccionaron 1,500 registros con conversación textual completa
- Limpieza: Eliminación de vacíos, corruptos, duplicados exactos (~200)
- **Retención final: 10% (1,500/14,974)** — La mayoría de datos eran metadata de contacto sin conversación

Detalles completos: Ver `05_documentacion/REPORTE_CONSOLIDACION_4_BASES.txt`
